## 域1：认证与身份

### 认证路径总览

octo-server 共有 **4 条**主要认证路径，均汇聚到同一个 Redis token 缓存作为真相源。

> **关于 cookie 认证路径：octo-server 自身不使用 cookie 进行身份认证。**
> cookie 在源码中仅出现于 `pkg/i18n/` 包，用于读取 `i18n_lang` 字段判断用户语言偏好（优先级低于 `X-Octo-Lang` header 和 URL 参数）。OIDC 流程注释中提到的 cookie 是第三方 IdP 自身的域 cookie，不由 octo-server 设置或读取。
> 来源: `pkg/i18n/lang.go#L51-L73`

---

#### 路径 A：本地凭据登录（短信验证码 / 用户名密码 / 邮箱）

**场景**：普通用户通过手机 App 或 Web IM 登录，最终获得 `token`（UUID 字符串）。

| 端点 | 方法 | 路由 |
|------|------|------|
| 手机号+验证码 | POST | `/v1/user/login` |
| 用户名密码 | POST | `/v1/user/usernamelogin` |
| 邮箱登录 | POST | `/v1/user/emaillogin` |
| 认证码登录 | POST | `/v1/user/login_authcode/:auth_code` |

登录成功后，系统执行以下动作（核心函数 `execLogin`）：
1. 在 Redis 写入 `token:<uuid>` → `v2:<JSON>` 或 `v3:<JSON>`，TTL = `cache.tokenExpire`（默认 720h）
2. 调用 `ctx.UpdateIMToken` 将同一 token 同步给**悟空 IM（WuKong IM）**，后者负责长连接握手

**关键文件**：  
- 来源: `modules/user/api.go#L379-L401`（路由注册）  
- 来源: `modules/user/api.go#L1781-L1951`（`execLogin` token 签发主逻辑）  
- 来源: `modules/user/api.go#L1916-L1934`（`UpdateIMToken` 同步 IM）

---

#### 路径 B：API 请求时的 token 校验（HTTP Bearer / 自定义 `token` 头）

**场景**：已登录用户每次 API 请求时，身份验证中间件（`AuthMiddleware`）读取 token 并解析用户身份。

- 客户端可发 `token: <uuid>` 自定义头，或 `Authorization: Bearer <uuid>` 标准头
- 兼容层 `BearerTokenCompat` 中间件负责把 Bearer 头回填为 `token` 头（`token` 头优先）
- `CacheTokenParser.Parse` 从 Redis 读 payload，支持三种格式：
  - 旧格式：`uid@name[@role]`（legacy，灰度期只读）
  - v2：`v2:{"uid":...,"name":...,"role":...,"lang":...}`
  - v3：`v3:{...加上 issued_at / expires_at / session_generation / session_revision}`
- 每次解析均通过 `RoleResolver` 从 DB/缓存实时刷新系统角色（`admin`/`superAdmin`），防止降权后 token 继续生效

**关键文件**：  
- 来源: `pkg/wkhttp/bearer_compat.go#L1-L68`（Bearer 兼容中间件）  
- 来源: `pkg/auth/parser.go#L67-L210`（`CacheTokenParser.Parse` 主链路）  
- 来源: `pkg/auth/tokeninfo.go#L1-L180`（v2/v3 格式编解码）  
- 来源: `pkg/auth/validator.go#L1-L80`（`TokenValidator.Validate` v3 严格校验）  
- 来源: `main.go#L207-L228`（启动时 Redis Lua 探针 + 注入 TokenParser）

#### 路径 C：OIDC / OAuth2 / HS256 JWT 第三方登录

**场景**：企业 SSO 接入，或原生 App 用客户端业务 JWT 换取 octo session token。

| 端点 | 方法 | 功能 |
|------|------|------|
| `/v1/auth/oidc/<id>/authorize` | GET | 生成 state/PKCE，302 跳 IdP |
| `/v1/auth/oidc/<id>/callback` | GET | IdP 回调，验证 code，签发 session token |
| `/v1/auth/oidc/<id>/exchange` | POST | 上游 OIDC access_token → 身份 → session token |
| `/v1/auth/oidc/<id>/exchange-jwt` | POST | 客户端业务 HS256 JWT → session token（本地验签，无外呼）|
| `/v1/auth/oidc/<id>/logout` | POST | 吊销 session，通知 IdP（authed 路由）|

- OIDC 整体开关：环境变量 `DM_OIDC_ENABLED`（默认 `false`，关闭时所有端点返回 404）
- exchange 端点独立开关：`OCTO_OIDC_EXCHANGE_ENABLED`（默认 `false`）
- 成功换取 session 后走与路径 A 相同的 token 签发流程（`execLogin` 下游）

**关键文件**：  
- 来源: `modules/oidc/api.go#L367-L430`（路由注册，含 enabled/disabled 分支）  
- 来源: `modules/oidc/config.go#L131-L155`（配置读取，`DM_OIDC_ENABLED`）  
- 来源: `modules/oidc/api_exchange_jwt.go#L1-L55`（HS256 JWT exchange 说明）

#### 路径 D：Bot / Daemon API Key 验证（机器对机器）

**场景**：fleet/matter 等内部服务或 Bot 通过 API Key 访问 octo-server。

| 端点 | 方法 | 凭据类型 | 说明 |
|------|------|---------|------|
| `/v1/auth/verify` | POST | 用户 session token | 返回 uid+角色+owned_bots；?include=context 额外返回 space 成员关系 |
| `/v1/auth/verify-bot` | POST | Bot token（BotFather Bearer token）| 返回 bot_uid/owner_uid/space_id |
| `/v1/auth/verify-api-key` | POST | Daemon API Key（`uk_` 前缀）| 返回 uid+space_id；同时校验 user.status=1 + space.status=1 |

- Bot token 查 `robot.bot_token` 列（`status=1`）
- API Key 查 `user_api_key.api_key` 列（`status=1, client_id='botfather', space_id!=''`）
- 三个端点都挂 `verifyLimit` 限流，不挂 `AuthMiddleware`（未认证端点）

**关键文件**：  
- 来源: `modules/user/api.go#L404-L406`（路由注册）  
- 来源: `modules/user/api.go#L4740-L4830`（`authVerifyToken` 实现）

- 来源: `modules/user/api.go#L5055-L5150`（`authVerifyAPIKey` 实现）

#### WuKong IM 长连接握手

**场景**：移动/桌面客户端建立 IM 长连接时，悟空 IM 使用登录时同步过去的 token 做握手鉴权。

- octo-server 不直接处理 WebSocket 握手，而是在登录时调用 `ctx.UpdateIMToken`（悟空 IM 管理 API）将 token 注册到 IM 层
- 悟空 IM 配置：`wukongIM.apiURL` + `wukongIM.managerToken`
- 若 `UpdateIMToken` 失败，octo-server 会回滚已签发的 token（补偿机制）

**关键文件**：  
- 来源: `modules/user/api.go#L1916-L1934`（`UpdateIMToken` 调用与补偿）  
- 来源: `configs/tsdd.yaml#L21-L24`（悟空 IM 配置段）

## 域2：鉴权模型

### 鉴权层级（从粗到细，低层覆盖不了高层）

```
系统级 RBAC（admin/superAdmin）
    ↓ 覆盖范围：全服务所有管理端路由
Space 成员角色（owner/admin/member）
    ↓ 覆盖范围：特定 Space 内的资源操作
频道 / 群组 ACL（成员检查）
    ↓ 覆盖范围：单个频道/群组的读写访问
Bot / API Key 身份门禁（authtree 租户隔离）
    ↓ 覆盖范围：uk_ / bf_ 凭据下的 Space 边界
```

---

### 系统级 RBAC（org 级）

三个系统角色（存入 token payload，同时通过 `RoleResolver` 实时刷新）：

| 角色 | 权限范围 |
|------|---------|
| `superAdmin` | 全部管理端操作，含高危/不可逆操作（强制解散 Space、用户封禁、重置密码） |
| `admin` | 只读 + 低风险管理操作，不含 Space 销毁、跨 Space 强制操作 |
| `dashboardReader` | 仅开放 `/v1/manager/dashboard/*` 读面（不出现在 octo-lib `CheckLoginRole`，仅本服务生效）|
| `marketAdmin` | 仅开放 octo-marketplace MCP/Skill/Expert 目录管理面（不出现在 octo-lib，需 re-login 才生效；吊销角色后必须同时吊销 session）|

- **`CheckLoginRole`**（octo-lib）：接受 `admin ∪ superAdmin`，用于大多数管理接口
- **`CheckLoginRoleIsSuperAdmin`**：仅 `superAdmin`，用于高危操作
- **`IsManagerConsoleRole`**（本服务）：`admin ∪ superAdmin ∪ dashboardReader ∪ marketAdmin`，用于允许进入管理控制台
- **`CanAdminMarketplace`**（本服务）：`superAdmin ∪ marketAdmin`，用于广告目录管理

> ⚠️ 注意：`marketAdmin` 角色存在已记录的安全陷阱：  
> - **授予不生效**直到持有人重新登录（token snapshot 未更新）  
> - **吊销不立即生效**（marketplace 通过 `/v1/auth/verify` token snapshot 验证，在 token 生命周期内继续有效，最长 720h）  
> - 必须同时吊销 session，且还有约 30s 的 marketplace 自身 AUTH_CACHE_TTL 残留窗口

**关键文件**：  
- 来源: `pkg/auth/manager_roles.go#L1-L90`（4 个角色定义 + 策略函数）  
- 来源: `modules/user/api_manager.go#L116-L200`（管理端路由 + `managerCapabilities` 能力表）  
- 来源: `modules/space/api_manager.go#L159-L180`（`requireAdmin` / `requireSuperAdmin` 封装）

### Space 成员角色（Space 级 RBAC）

Space 成员角色存储在 `space_member.role` 列：

| 值 | 角色 | 权限 |
|----|------|------|
| `0` | member（普通成员）| 只能操作自己的资源 |
| `1` | admin（管理员）| 可修改成员角色（不含 owner），管理频道 |
| `2` | owner（拥有者）| 全部权限，包括解散 Space、转让 owner |

- **修改成员角色**：只有 `role=2`（owner）才能调用，且 owner 不能被直接降级（必须转让后降）
- **转让 owner**：原子操作（`SELECT ... FOR UPDATE`），防并发竞态
- 系统管理员（`superAdmin`）通过管理端 API 可强制修改任意 Space 的成员角色（`requireSuperAdmin` 保护）

**关键文件**：  
- 来源: `modules/space/model.go#L38`（角色常量注释：0=普通 1=管理员 2=拥有者）  
- 来源: `modules/space/api.go#L94`（路由：`PUT /:space_id/members/:uid/role`）  
- 来源: `modules/space/api.go#L937-L1010`（`updateMemberRole` 完整实现，含防无主空间逻辑）  
- 来源: `modules/space/api_manager.go#L159-L180`（管理端角色定义）

### 频道 / 群组 ACL

频道读取（`GET /v1/channels/:channel_id/:channel_type`）有三级对象级授权：

| 频道类型 | 授权方式 | 失败响应 |
|---------|---------|---------|
| `ChannelTypeGroup`（群组）| 检查 `groupService.ExistMember`（活跃成员）| 403 `ErrGroupViewForbidden` |
| `ChannelTypeCommunityTopic`（子区）| 继承父群 ACL，检查父群 `ExistMemberActive` | 403 `ErrGroupViewForbidden` |
| `ChannelTypePerson`（单聊）| 检查可见关系（`personProfileVisible`）；无关系时降级返回最小集（仅名/头像），不做二元 403 | 最小集降级 |

- 子区存在性不泄露（与"非父群成员"统一返回 forbidden）
- 单聊场景不硬拒——保留历史消息发送者渲染能力（跨 Space 成员裂图防护）

**关键文件**：  
- 来源: `modules/channel/api.go#L180-L260`（三类频道的对象级授权逻辑）  
- 来源: `modules/channel/channel_get_authz_test.go`（授权专项测试）

### Bot / API Key 身份门禁（authtree 租户隔离）

两棵认证树，通过 `pkg/authtree` 注册，分别处理 `uk_*`（用户 API Key）和 `bf_*`/`app_*`（Bot token）：

**TreeUserKey（`uk_*` API Key，Space 级租户隔离）**

- 每个 API Key 在签发时冻结一个 `space_id`
- 所有路由由 `enforceKeySpace` 中间件拦截，确保请求操作的资源属于该 Space
- 特例：`GET /file/download/url` 标记为 `ScopeUnscoped`（⚠️ 待确认完整对象级隔离）

**TreeBotToken（`bf_*`/`app_*` Bot token）**

- `KindUserBot`（`robot` 表）：无 Space 冻结，通过活跃群成员校验访问群资源
- `KindAppBot`（`app_bot` 表）：可能有 `scope=space` + `space_id` 限制，通过 `appBotScopeGuard` 强制 peer 必须是绑定 Space 的成员

**botidentity 解析器**：两类 bot 身份从 `robot` 和 `app_bot` 两张表联合查询（单次快照），强制 cross-table 唯一性（`ErrAmbiguousIdentity`）

**关键文件**：  
- 来源: `pkg/authtree/authtree.go#L1-L150`（两棵认证树的租户隔离全量说明）  
- 来源: `modules/botidentity/resolver.go#L1-L120`（Bot 身份解析器，联合 robot + app_bot）  
- 来源: `modules/botidentity/resolver.go#L61-L74`（单次 SQL snapshot 防竞态）

### 不启用 / 条件启用汇总

| 模块 | 条件 | 未满足时的行为 |
|------|------|--------------|
| `oidc` | `DM_OIDC_ENABLED=true` | 所有端点返回 404 |
| `oidc` exchange 端点 | `OCTO_OIDC_EXCHANGE_ENABLED=true` | POST /exchange / /exchange-jwt 不挂载（连限流 Redis client 都不构造）|
| `usersecret` | `OCTO_MASTER_KEY`（32 字节）| `enabled=false`，写接口返回内部错误，resolve 端点同理 |
| `voice_adapter` | `SPEECH_SERVICE_URL` | 路由存在，请求失败并 warn log |
| `agentmailgateway` | `OCTO_MAIL_GATEWAY_URL` + `OCTO_MAIL_GATEWAY_SECRET` | 同时缺失→完全禁用；只有一个→启动 warn |
| `internal_resolve` | `OCTO_INTERNAL_RESOLVE_TOKEN`（足够长且不与其他内部 token 冲突）| 缺失/过短→所有请求拒绝（fail-closed）|
| `backup` | 配置中 `Enabled=true` | 调度不启动，管理端接口返回 disabled 状态 |
| `thread` | `DM_THREAD_ON` env | 关闭时停 API，保留 schema 迁移 |
