# octo-server 知识库 · 域5-7

## 域5：API 与错误约定

### 5.1 统一响应体格式

octo-server 通过 `pkg/httperr` 的 `ResponseErrorL` / `ResponseErrorLWithStatus` 统一渲染错误响应。正常响应由 octo-lib 的 `wkhttp.Context` 的 `ResponseOK` / `Response` 渲染，无统一包装层（直接返回业务 JSON）。

**错误响应 envelope（body）字段：**

```json
{
  "status":      <int>,       // 语义 HTTP 状态码（如 401/403/429），与 error.http_status 相同
  "msg":         <string>,    // 本地化错误文案（zh-CN / en-US）
  "code":        <string>,    // i18n 错误码 ID，如 "err.shared.auth.required"
  "http_status": <int>,       // canonical HTTP status（与 wire status 可能不同，见 D14）
  "details":     <object>     // SafeDetailKeys 白名单内的补充信息，如 {"field":"username"}
}
```

**兼容性说明（D14）：**
- 绝大多数 legacy 端点 wire HTTP status = 400（兼容老客户端），body 内 `http_status` 字段仍为真值（如 401/403）
- 新端点（OIDC/Bot bind/notification 设置等）用 `ResponseErrorLWithStatus`，wire status = 语义值

来源: `pkg/httperr/respond.go#L1-L82`
来源: `pkg/i18n/codes/registry.go#L1-L60`

### 5.2 错误码分类

错误码分两个命名空间：

| 命名空间 | 位置 | 含义 |
|---|---|---|
| `err.shared.*` | `pkg/i18n/codes/shared.go` | 跨模块通用（认证/鉴权/限流/参数/内部） |
| `err.server.*` | `pkg/errcode/*.go` | 模块专属业务错误 |

错误码格式规则：`err.(shared|server).<domain>.<reason>`，全小写点分，在 `init()` 阶段 `Register()` 注册，重复 ID 直接 panic。

典型 shared 错误码：

| 错误码 ID | HTTP 状态 | 含义 |
|---|---|---|
| `err.shared.auth.required` | 401 | 未登录 |
| `err.shared.auth.token_missing` | 401 | token 缺失 |
| `err.shared.forbidden` | 403 | 无权限 |
| `err.shared.not_found` | 404 | 资源不存在 |
| `err.shared.rate.limited` | 429 | 限流 |
| `err.shared.internal` | 500 | 服务器内部错误（Internal=true，不输出内部 msg） |

来源: `pkg/i18n/codes/shared.go#L1-L40`
来源: `pkg/i18n/codes/registry.go#L30-L60`
来源: `pkg/errcode/server.go#L1-L50`

### 5.3 HTTP 状态码映射

**两种渲染路径：**

1. **ResponseErrorL（legacy 兼容）**：wire status 固定 400，body `http_status` = 语义值
2. **ResponseErrorLWithStatus（新端点）**：wire status = body `http_status` = 语义值

`Internal=true` 的错误码（5xx）：renderer 输出占位文案，不泄漏内部 message。

## 域6：IM 控制面

### 6.1 整体分工

octo-server 与 WuKongIM 的关系：octo-server 是**控制面**，WuKongIM 是**数据面（消息内核）**。

| 操作 | 走哪里 |
|---|---|
| 消息发送（业务） | octo-server `/v1/message/send` → `ctx.SendMessage()` → WuKongIM `/message/send` |
| 消息同步（拉取） | octo-server → `ctx.IMSyncMessage()` → WuKongIM |
| 频道创建/更新 | octo-server → `ctx.IMCreateOrUpdateChannel()` → WuKongIM |
| 频道订阅者管理 | octo-server 群组模块维护成员后，`SendChannelUpdateToGroup()` 通知 WuKongIM |
| 消息搜索 | octo-server → WuKongIM `/message/search`（或 Zinc 索引，需显式配 backend=zinc） |
| WebSocket 长连接 | 客户端**直连 WuKongIM**，不经过 octo-server |
| 实时推送/在线状态 | 客户端 WebSocket 直连 WuKongIM，octo-server 不介入 |

### 6.3 分工边界总结

- **octo-server 负责**：业务逻辑（鉴权/成员管理/消息体 enrich/群组操作/撤回软删除/卡片渲染）
- **WuKongIM 负责**：消息持久化、消息推送、WebSocket 长连接、在线状态、消息路由
- **octo-server 不负责**：WebSocket 握手、实时推送、消息存储

| 模块 | 职责 |
|---|---|
| `botfather` | **User Bot（机器人账号）的生命周期管理**：注册/审批/发布/心跳/事件队列。面向开发者。 |

### 7.2 Bot 身份体系

**两类 Bot：**

1. **User Bot（robot 表）**
   - 通过 `botfather` 模块注册
   - 凭据前缀：`uk_`（user-bot key）或 `bf_`（botfather key）
   - 通过 botfather 申请/审批流上线
   - 心跳维持在线状态，有事件队列

2. **App Bot（app_bot 表）**
   - 通过 `app_bot` 模块创建
   - UID 格式：`app_<id>_bot`，token 前缀：`app_`
   - 两个 scope：`platform`（全局）/ `space`（Space 内）
   - 有 Status 状态机：Draft(0) → Published(1) / Unpublished(2)

### 7.3 Agent 会话怎么起

Agent 会话通过 `agentmailgateway` 模块代理：

1. **路径**：浏览器 → octo-server `/v1/mail-gateway/*` → agentmailgateway → 上游 octo-mail WebAPI
2. **认证**：用户在 octo-server 已登录，agentmailgateway 用请求绑定的短期 assertion 代替用户凭据，不透传原始 token
3. **身份预配（provisioning）**：每个 `uid + spaceID` 组合在首次请求时调用 `ensureProvisioned()`，通过 `/internal/v0/gateway-identities/ensure` 向 octo-mail 注册身份；后续命中 LRU 缓存（最多 4096 条），不重复预配
4. **配置**：通过环境变量 `OCTO_MAIL_GATEWAY_URL` / `OCTO_MAIL_GATEWAY_SECRET` / `OCTO_MAIL_GATEWAY_TIMEOUT` 启用；未配置时该模块路由直接返回 `errGatewayNotConfigured`（条件启用）

### 7.4 bot_mention 模块

`bot_mention` 是独立注册模块，职责是接收来自文档/消息服务的 @mention 事件并写入 Bot 事件队列。

- **路由**：`POST /v1/internal/bot-mentions`（内部服务接口，非对外公开）
- **认证**：内部 token（通过 `internalTokenHeader` 校验），与用户 token 体系完全独立
- **幂等**：通过 Redis claim store 防止同一 mention 事件重复处理（`Lookup` / `Begin` / `Commit` / `Release`）
- **事件下游**：调用 `botevent.Notify()` 通知 robot 模块处理
- **无 SQL 表**：`1module.go` 中无 `SQLDir` 注册，不维护独立数据表

### 7.5 Bot/Agent 与 WuKongIM 的关系

- Bot 发消息：通过 `bot_api` 模块的 `dispatchMsgSendReq()` → `ctx.SendMessage()` → WuKongIM
- Bot 收消息：WuKongIM webhook 推给 octo-server，再由 bot 事件队列分发
- App Bot 同 User Bot 使用相同的 WuKongIM 发送路径，区别在 UID 格式和 systemUID 白名单规则
- WebSocket：Bot 直连 WuKongIM，使用登录时下发的 token（与 API token 同源，通过 `bot_provision` mintBot 签发）
